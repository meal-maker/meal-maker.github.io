### [Anthropic launches opt-in AI vulnerability scanning for open source](https://www.anthropic.com/research/launching-opt-in-vuln-finding-service-for-open-source) ⭐️ 8.0/10

Anthropic has launched OSS Scanner, a free opt-in vulnerability scanning service for eligible open source projects. The reports are generated by Claude and other models without human review, and include vulnerability reproduction steps, explanations, and patch suggestions where possible; they may contain errors. Over the past six months, the service found more than 29,000 candidate vulnerabilities, of which about 6,000 were manually reviewed. **「Impact」** Eligible open source maintainers can opt in to receive free AI-generated vulnerability reports, potentially surfacing serious issues earlier, but must verify findings because the reports are not human-reviewed.

### [ThinkingBox: 507 Stateful Workflows Graded on Terminal Database State Across 20 Runs](https://www.reddit.com/r/MachineLearning/comments/1x17shf/thinkingbox_solving_an_agent_task_once_vs_solving/) ⭐️ 7.0/10

Microsoft researchers introduced ThinkingBox, a public benchmark of 507 policy-conditioned business workflows across retail, travel/hospitality, auto insurance, neobank internal IT, and consulting IT/HR. Each task is executed 20 times from an identical clean backend—10,140 trials per model—with grading based on terminal backend state and side effects, not just completion. The benchmark defines pass@1, pass@20, and all-20, and reports that discovery and repeatability rank models differently: Kimi-K3 solved 93.89% of tasks at least once but only 13.41% on all 20 attempts, while Claude Opus 5 solved 79.09% at least once and 47.53% on all 20. A retrospective analysis of 121,680 valid trials across 12 models found 79,853 executable-check failures, of which 67.24% still terminated cleanly with a state-changing tool and no final tool error. Among those clean-terminating failures, wrong field values appeared in 77.61% of cases, unintended extra effects in 43.30%, and missing required effects in 25.36%, showing completion-style proxies miss incorrect backend state.

reddit · r/MachineLearning · /u/tuhin\_k · Oct 9, 00:50

**「Background」** Agent evaluations often treat a task as successful if the model ends without a tool error or returns a plausible final response, which can miss incorrect changes to persistent backend state. ThinkingBox addresses this gap with a reusable sandbox for verifiable tool-agent-user interaction and a benchmark of 507 stateful business workflows across retail, travel/hospitality, auto insurance, neobank internal IT, and consulting IT/HR. Each task is run 20 times from an identical clean backend, and grading compares the terminal database state and side effects against the required end state, reporting pass@1, pass@20, and all-20 to separate discovery from repeatability.

**「Impact」** This gives agent developers and enterprises a reproducible way to measure backend-state correctness and repeatability, showing that pass@1 and pass@20-style metrics can mask unreliable repeated execution—for example, Kimi-K3 discovered 93.89% of tasks yet solved only 13.41% on every one of 20 attempts.

### [ARTEX and LLM Relay Used Against Korean Financial Institutions](http://xcai.pro/) ⭐️ 7.0/10

CrowdStrike reported on October 7 that an unidentified attacker targeted Korean financial institutions between late September and early October, stealing data using ARTEX, a Chinese-developed open-source agent penetration tool. The vendor assessed with medium confidence that the actor is a Chinese speaker with financial motivation but has not attributed the activity to a known group. In an attacker-controlled open directory, CrowdStrike found Claude Code session logs and ARTEX configuration files showing use of the relay xcai.pro with DeepSeek v4.1-flash, plus Zhipu GLM-5.3 and Grok 4.6 as auxiliary models. One session requested generation of a security researcher resume containing age 26, a South China University of Technology background, and Guangdong Maoming, which the company says likely belongs to the attacker. Identity and the scale of data theft remain unconfirmed, and the suspected relay has since been shut down.

telegram · zaihuapd · Oct 8, 10:32

**「Background」** ARTEX is an open-source agentic penetration-testing tool that integrates large language models to automate offensive security tasks; in this campaign it was paired with Claude Code and multiple LLMs accessed through a relay service such as xcai.pro. CrowdStrike&\#x27;s analysis indicates the attacker hosted an ARTEX instance and an open directory at IP 38.244.50.120, where configuration files and Claude Code session logs were exposed, allowing reconstruction of the tool usage and model calls.

**「Impact」** Korean financial institutions targeted in the operation face potential data theft, although the exact scope of compromised data and victim organizations has not been confirmed.

Reported short-context pricing is about $12 per million input tokens, $0.60 per million cached input tokens, and $60 per million output tokens. The information comes from a Telegram post referencing Tibo&\#x27;s 28-day update series; no independent verification or further technical details are provided.

telegram · zaihuapd · Oct 9, 00:00

**「Background」** Ultrafast mode is the fastest service tier in the OpenAI API, broadly available for GPT-6 Astra and GPT-6.1 Sol, with preview access for GPT-5.6 Sol. It offers up to 8x faster generation than Sol Standard and is priced at 6x Standard—$12 per million input tokens and $60 per million output tokens—which OpenAI notes is about 1.2x the cost of Astra. For latency-sensitive or agentic workloads, OpenAI recommends using WebSockets to avoid network overhead reducing the speed gains.

**「Impact」** Developers using the OpenAI Responses API can now access a GPT-6.1 Sol Ultrafast tier that delivers up to 8x generation speed at 6x Standard pricing—$12 per million input tokens, $0.60 per million cached input tokens, and $60 per million output tokens for short context—making it a high-cost option for latency-sensitive applications.
