### [Claude Reveals NIST ECDSA Seeds Came from lrand48 and Timestamps](https://www.anthropic.com/research/ecdsa-curve-origins) ⭐️ 9.0/10

Anthropic&\#x27;s Claude AI discovered that the NIST P-192, P-224, P-256, P-384, and P-521 elliptic curve seeds were generated by the C library lrand48 pseudo-random number generator seeded with Unix timestamps, rather than by a hash-based process. The finding resolves a long-standing question about the origins of these standardized curve parameters and undermines theories that the seeds were backdoored. The fifth binary seed, B-163, does not fit the identified pattern and may contain a typographical error in its published value. The discovery is detailed in a write-up by Filippo Valsorda at words.filippo.io/seeds-solved/.

hackernews · ahlCVA · Oct 16, 18:55 · [Discussion](https://news.ycombinator.com/item?id=50122800)

**「Background」** The NIST elliptic curves used in ECDSA \(P-192, P-224, P-256, P-384, P-521\) were standardized with seed values that NIST said were generated by an unspecified method, leading to long-standing suspicion that they might have been deliberately chosen to give the NSA a backdoor. These concerns persisted because researchers could not reproduce the seeds using common hash-based constructions. The new finding, reported by Anthropic, is that Claude identified the seeds as outputs of the C library&\#x27;s lrand48 random-number generator seeded with Unix timestamps, with values corresponding to dates between May 1997 and April 1998.

**「Impact」** The result weakens a key argument against trusting NIST P-curves, but it does not prove that candidate curves were not selectively rejected during generation.

**「Community Discussion」** Commenters largely view the discovery as a significant blow to NIST curve backdoor conspiracy theories. Some caution that the method reveals how seeds were generated but cannot exclude discarding candidates with chosen properties, and the unexplained B-163 seed is suspected to be a typo.

### [Big Fish: Exploiting a 37-Year-Old Kernel Bug in OpenBSD](https://calif.io/research/big-fish) ⭐️ 8.0/10

A technical deep-dive examines exploitation of a 37-year-old kernel vulnerability in OpenBSD, a codebase known for extensive auditing. The analysis highlights how the bug survived for nearly four decades despite review, demonstrating the difficulty of catching long-lived kernel flaws. It discusses the exploit primitive and the conditions that made it viable. The work underscores that even heavily audited code can harbor deeply hidden, exploitable bugs.

hackernews · rs\_rs\_rs\_rs\_rs · Oct 16, 14:44 · [Discussion](https://news.ycombinator.com/item?id=50118977)

**「Background」** OpenBSD is a security-focused Unix-like operating system that emphasizes code audits and exploit mitigations. The reported chain targets a 37-year-old bug in the SysV shared memory attachment counter, a signed 16-bit short that can be overflowed by forking 259 processes, creating a use-after-free race. This is combined with an out-of-bounds write in IP multicast options handling to bypass SMAP/SMEP and gain root access, with the original flaw traceable to the original BSD source code.

**「Community Discussion」** Commenters noted the same bug was accidentally fixed in NetBSD during an August 1999 rewrite, and observed that its 37-year survival in OpenBSD shows the limits of manual review. One commenter asked whether fuzzing or static analysis could realistically find this class of bug, or whether it required human thinking about the exploit primitive.

### [Open-Source ORL Speeds Diffusion LLMs to 2,788 Tokens/s on RTX 5090](https://www.reddit.com/r/MachineLearning/comments/1x7qgr0/research_2788_tokenss_on_a_single_rtx_5090_with_a/) ⭐️ 8.0/10

Researchers introduced ORL \(On-Policy Residual Learning\), an open-source method and custom inference engine dlmrt that accelerates diffusion language models. It reports 2,788 tokens/s on a single RTX 5090 with LLaDA-2.1-mini and 7,708 tokens/s on 8× B200 with DiffusionGemma 26B MoE, both at NVFP4. ORL achieves up to 6.9× higher end-to-end throughput on QwenDLM-4B at comparable or better quality, and 1.74× faster than DFlash speculative decoding at matched accuracy in a single-request H100 comparison. The method uses on-policy residual learning to refine previous predictions and a loss called Adjacent Entropy Contraction to reduce uncertainty faster. All numbers are for batch size 1 peak results on specific benchmarks, and code, models, and evaluation are open source.

reddit · r/MachineLearning · /u/arty\_photography · Oct 16, 20:03

**「Background」** Diffusion language models generate text by iteratively refining many tokens in parallel over multiple denoising steps, unlike autoregressive LLMs that emit one token at a time. Their speed depends on reducing the number of forward passes until tokens are finalized. ORL&\#x27;s residual context carries forward previous predictions so the model can converge in fewer steps.

**「Impact」** Developers running diffusion LLMs such as QwenDLM-4B or LLaDA-2.1-mini on single NVIDIA GPUs can adopt the open-source ORL training method and dlmrt engine to boost single-request decoding throughput by up to 6.9× compared to the baseline, with reported examples including 2,788 tokens/s on an RTX 5090 and 1,298 tokens/s on an H100. The reported gains are peak single-request benchmark figures and may not reflect average throughput across arbitrary workloads.

The approach begins on a single Mac Studio with up to 512GB of unified memory and then scales across multiple machines.

hackernews · antipaul · Oct 16, 13:43 · [Discussion](https://news.ycombinator.com/item?id=50118320)

The model discussed, Muse Spark Open, is an open-weight large language model developed by Meta and optimized in collaboration with Apple to run on Apple hardware; at roughly 816 billion parameters it is too large for a single Mac Studio, so MLX supports pipelining across multiple Mac Studios using RDMA.

**「Impact」** Developers can run the near-trillion-parameter Muse Spark Open model locally on a cluster of four Mac Studios with MLX at up to 36 tokens per second, though the demonstrated 8,192-token context is shorter than many current production workloads require.

**「Impact」** Developers and organizations needing agentic AI with long context and multimodal input can access the Step 5 Preview 600B-parameter sparse MoE model via an OpenAI-compatible API under the StepFun Model License 1.0, but as a preview release its independent benchmark results and production reliability are not yet established.
