## [2027 DRAM Capacity Sold Out Due to AI-Driven HBM Demand](https://www.ign.com/articles/ramageddon-continues-another-year-as-2027-memory-capacity-is-reportedly-sold-out) ⭐️ 8.0/10

Memory capacity for 2027 is reportedly sold out due to surging demand for high-bandwidth memory (HBM) used in AI accelerators, leading to potential shortages in the overall DRAM industry. The depletion of future memory supply highlights how AI's rapid growth is straining semiconductor resources, potentially driving up prices and limiting availability for consumer and other computing applications. HBM production consumes approximately three times the wafer supply as DDR5 to produce the same number of bits, significantly constraining non-HBM memory output.

hackernews · inigyou · Aug 7, 07:58 · [Discussion](https://news.ycombinator.com/item?id=49207236)

**Background**: High-bandwidth memory (HBM) is a 3D-stacked DRAM technology that offers much greater data throughput than traditional memory like DDR5, making it essential for AI accelerators such as GPUs. The manufacturing process requires larger dies and advanced packaging, which consumes more silicon wafer area per bit. As AI demand skyrockets, memory makers are prioritizing HBM production, leaving less capacity for other DRAM types. This shift impacts the entire memory industry, potentially leading to shortages for PCs, servers, and other devices.

## [Assembly Hall of Shame: Documenting Slow x86 Instructions](https://github.com/xoreaxeaxeax/asm-hall-of-shame) ⭐️ 6.0/10

A new GitHub repository named 'Assembly Hall of Shame' has been created, humorously compiling notoriously slow x86 assembly instructions, such as a 12ms ACPI IO port write that likely traps to System Management Mode. Although primarily humorous, the repository highlights real performance quirks in x86 processors, educating low-level developers and system programmers about instruction timing and microarchitectural pitfalls that can affect performance-critical code. The repository enforces rules that trapped or emulated instructions only measure the trap time, not the handler; however, the 12ms ACPI IO write at position 8 likely involves actual SMM handling. Other notorious slow instructions include LODSW and complex microcoded operations.

hackernews · piotrgrabowski · Aug 7, 18:01 · [Discussion](https://news.ycombinator.com/item?id=49214098)

**Background**: x86 assembly instructions vary widely in execution time. Some are slow because they are microcoded into many internal operations, while others may trap to System Management Mode (SMM) for specialized hardware access. Historically, instructions like LODSW became slower than equivalent small code sequences due to shifts in hardware design priorities, making performance engineering a nuanced task.
