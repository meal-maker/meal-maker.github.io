### [vLLM v0.30.0 Adds DeepSeek V4 Support and Fast GPU Cache](https://github.com/vllm-project/vllm/releases/tag/v0.30.0) ⭐️ 8.0/10

vLLM v0.30.0 has been released with 762 commits from 315 contributors, adding support for several new models including DeepSeek-V4.1-Flash, DeepSeek-V4-Flash-Vision-Exp, GLM-5.3-Flash, K2-Horizon, Cohere Compass, Bailing V3 VL, Nanbeige4.2, and a DeepSeek-V4 CPU backend. The release introduces a persistent per-GPU weight-cache daemon that holds post-quantized, TP-sharded weights in GPU memory, allowing engines to restart using CUDA IPC with \`--load-format ipc\_cache\` instead of reloading from disk, now covering FP4 checkpoints and multi-node tensor parallelism. Other additions include Gumbel-max watermarked generation and detection, the HiSparse host-resident tier for sparse-MLA decode, Model Runner V2 improvements such as dual-batch overlap and full CUDA graph support, and expanded quantization options including targeted online quantization and W4A16 DSA. Breaking changes require scale-out endpoints to be enabled via \`--enable-scale-out\` on \`vllm serve\`, remove GPTQ activation ordering \(\`g\_idx\`\), and deprecate the \`all\` Mamba cache mode and \`python -m vllm.entrypoints.grpc\_server\`.

github · khluu · Sep 22, 05:20

**「Background」** vLLM is an open-source LLM inference engine known for high-throughput serving and features such as PagedAttention, continuous batching, and support for many model architectures. Recent releases have focused on DeepSeek model variants and large-scale serving optimizations; v0.30.0 continues this with a persistent weight cache that avoids reloading quantized weights from disk when engines restart.

**「Impact」** Users upgrading to v0.30.0 must update deployment configurations because scale-out endpoints are now opt-in via \`--enable-scale-out\` and GPTQ activation ordering has been removed, but they can reduce restart latency by adopting \`--load-format ipc\_cache\`.

A fix was released in WordPress 7.1.2 and backported to all supported branches back to version 4.7. WordPress 7.1.2 contains the fix, with backports provided for branches as old as 4.7.

**「Impact」** WordPress installations on versions 4.7.0 through 7.1.1 are exposed to unauthenticated remote code execution through the page-template path traversal, and attackers began actively scanning for the flaw within hours after the 7.1.2 fix was published.

### [DeepSeek and Tsinghua Release DSec Sandbox Platform Report](https://arxiv.org/abs/2609.22978) ⭐️ 8.0/10

DeepSeek-AI and Tsinghua University published a technical report on DeepSeek Elastic Compute \(DSec\), a sandbox infrastructure for large-scale AI agent training and evaluation. The platform exposes a unified SDK with four backends—FnCall, containers, Firecracker microVMs, and full VMs—and supports workloads such as online-judge tasks, software engineering, security testing, and computer operation. DSec decouples stateful rollout execution from preemptible GPU training and serves about 3 million sandbox instances per day on a production unit of about 160 nodes, with peak concurrency over 380,000 and creation rates above 5,000 per second. It uses the 3FS distributed filesystem to load EROFS images on demand, cutting task completion time by 1.7x and disk writes by 57% compared with full Docker pulls. Memory sharing and reclamation reduce peak memory use by about 40%.

telegram · zaihuapd · Sep 22, 04:45

**「Background」** Training AI agents with reinforcement learning requires safely executing many generated actions in isolated environments, often called sandboxes, so failures or hostile behavior cannot affect the host. A sandbox may be implemented as a lightweight function-call sandbox, an OS container, a Firecracker microVM, or a full virtual machine, with trade-offs between isolation and startup cost. DSec integrates these sandbox backends with reinforcement-learning infrastructure to separate long-running rollout tasks from GPU training jobs.

**「Impact」** Teams operating RL agent infrastructure can use DSec as a reference design, as its single 160-node unit supports 3 million daily sandboxes, over 380,000 peak concurrent instances, and per-node densities of 3,200 containers or 800 microVMs.
