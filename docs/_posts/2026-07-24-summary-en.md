## [ATProto's Public-by-Default Data Model Sparks Privacy Design Debate](https://lukekanies.com/writing/building-on-atproto/) ⭐️ 8.0/10

Luke Kanies' article highlights challenges with ATProto’s public data model, sparking a substantive discussion on permissions, privacy, and decentralized application design. This debate exposes a critical design tension between protocol openness and user privacy, influencing future development of decentralized social apps and affecting both developers and users. Key details include the current proposal’s URI-based locational permissions, and the community’s acknowledgment that default private data would undermine ATProto’s read-sharing architecture.

hackernews · speckx · Jul 23, 18:23 · [Discussion](https://news.ycombinator.com/item?id=49025984)

**Background**: AT Protocol (atproto) is a decentralized protocol powering Bluesky, designed with public data and self-authenticating records for interoperability. It uses a federated model with user-owned Personal Data Servers (PDS), where all data is public unless access controls are added. This contrasts with ActivityPub’s typically bounded sharing model.

**Background**: OpenGL is a cross-language, cross-platform API for rendering 2D and 3D vector graphics. Modern OpenGL, starting from version 3.3, introduced a programmable pipeline where developers write shaders in GLSL to control the GPU. Due to the complexity of graphics programming, comprehensive tutorials like LearnOpenGL are vital for newcomers to build a solid understanding before moving to lower-level or more advanced APIs.
